# Saved controlled teaching experiments

Additive T16 work: append `<TeachingWorkbench catalog={catalog} manifest={manifest} state={state} onChange={onChange} onCompare={optionalSaveComparison}/>` after the existing three lessons. `onCompare(baseline,candidate)` receives exact canonical states; parent owns comparison persistence. No existing lesson is replaced. Named export: `TeachingWorkbench`; prop type: `TeachingWorkbenchProps`.

The notebook starts collapsed, can be dismissed/restored, and uses normal accessible tables with units rather than a new plotting implementation. Six experiments isolate array height, antenna height, tracking versus captured fixed array orientation, constant load, usable storage and transmit power. Each includes intuition and scope limits through the existing Info component. Geometry is kept distinct from assumed usable-link performance. Height changes are independent, not shared-observer demonstrations.

Workflow: choose experiment → predict → capture the current scenario and its actual assessment → change exactly the allowed field → reveal and save computed values → write/edit learner explanation. Captured baseline remains locked when the shared scenario changes elsewhere. Records retain both exact states, input identities, data/model identity, changed path, locked-field policy, expected relationship, source IDs, before/after metrics, prediction and explanation. Reveal calls the authority for the candidate; baseline is evaluated on capture. Unknown values stay unavailable; no-change statements apply only to the tested stay. Full manifest identity changes invalidate an in-memory capture. Apply uses the exact candidate; optional comparison saving receives both states. Canonical scenario validation protects application inputs.

Records persist at `solarreach-teaching-v1`, with a separate versioned draft key preserving predictions, explanation, choice and baseline input across audience changes. Restoration reevaluates the captured input using the current manifest; it does not reuse cached science. Storage is bounded to 20 records and a 2 MB serialized envelope; text inputs are bounded. Storage failures are visible and do not erase the in-memory notebook. Reset clears experiment controls, preserving records and parent-owned saved comparisons. Record deletion is explicit. At 20 records, saving requests explicit deletion first; records never roll off automatically. Print records to retain a longer history.

Print worksheet opens a separate window with escaped text and embedded captured inputs/identities; no external PDF dependency or unescaped learner HTML. Popup blocking is reported. Print and browser focus behavior still need integrated browser/manual review.

The outage-order fixture is explicitly synthetic, not NASA measurement. Both cases have 48 hourly intervals, 24 dark hours, ideal 200 W generation when lit, 100 W demand, 1000 Wh initial/full capacity and unit charge/discharge efficiency: ideal autonomy 10 h. A has one continuous 24 h outage; B has four separated 6 h outages with 6 h recharge. Both run through the existing `evaluateMission`, not copied arithmetic. Actual results: A unmet demand 1400 Wh; B unmet demand 0 Wh and minimum stored energy 400 Wh; both generate 4800 Wh. A summary table and expandable hourly interval/power/end-battery table expose units and boundaries. This illustrates ordering under stated ideal assumptions, not general mission sufficiency.
