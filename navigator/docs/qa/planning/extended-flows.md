# Extended navigation, NASA models, global terrain and controls verification

The dedicated verifier is `scripts/verify-extended-flows.mjs`:

```sh
node scripts/verify-extended-flows.mjs --base-url http://127.0.0.1:4317 --output /tmp/solarreach-extended-http-final
node scripts/verify-extended-flows.mjs --file /absolute/path/solarreach-navigator.html --offline --output /tmp/solarreach-extended-offline-final
```

It uses the existing `playwright-core` and installed Chrome (`PLAYWRIGHT_CHROMIUM_EXECUTABLE` may override the default macOS path), a separate headless browser and fresh contexts at 1600×1000 CSS pixels/DPR 1. The main context has no reduced-motion preference; a second fresh context requests reduced motion. It never attaches to a user browser/profile or starts/stops/builds the application. The caller must wait for a coordinated preview build before running. For offline runs during parallel development, copy the completed standalone HTML to a byte-identical immutable temporary snapshot first so a rebuild cannot mix versions between contexts. The report fingerprints the actual tested HTML by SHA-256/byte count.

`extended-flows.json` records every pass/failure, browser version, page/console errors, relevant requests, browser navigation statuses, draw-counter diagnostics, actual exported decisions, viewport measurements and frame timing. `extended-progress.json` and per-check console messages are written during execution so failures can be reported immediately. Failures capture screenshots and stacks; exit 1 means at least one check failed. The existing independent terrain/frame validation gap is recorded separately as incomplete and is never promoted into physical certification by passing a browser check.

## Assertions

1. Starting at Connecting Ridge, select distant Apollo 11, observe outgoing zoom and Moon rotation, retarget to Apollo 17 before arrival, then observe incoming approach/completion. The latest selected state wins. Dates, displayed mission time, mission/flight assumptions and subsystem heights remain unchanged; environmental playback stays stopped.
2. From Moon overview, selecting Apollo 12 starts direct approach without redundant outgoing zoom/rotation. A real Chrome DevTools mouse-wheel input is armed on the first DOM-announced approach, cancels that navigation, then a fresh Apollo 15 selection completes. The gesture is sent through Chrome's input dispatcher, not a synthetic DOM wheel event.
3. Open **View controls → Surface & scale** and wait for both actual NASA model statuses to be ready. Focus **Sun**, then **Earth**. Each model's `Mesh.onAfterRender` counter must increase; save the focused textured-body screenshot plus notes and scene canvas. This proves actual mesh draw callbacks, beyond glyphs or ready text. Camera focus must not change scientific inputs. The served run also records successful local GLB responses; the offline run forbids all HTTP(S).
4. Place 20°N, 150°E. Coarse mode must show approximately 4.3 km output sampling, non-null modeled generation and partial global terrain evidence. Prepared-only mode must return unknown generation, never a zero/pass substitute. Re-enable coarse mode, save the exact scenario, share its UTF-8 inputs, export JSON, import and recompute. Coordinates, terrain mode and source IDs/hashes survive. Clipboard writing is intercepted in the isolated context to inspect the shared URL without changing the system clipboard.
5. On geometric windows, measure the **Stay length** and **Minimum Earth visibility** input rectangles at 1600 and 390 pixels. Their top edges must differ by no more than one CSS pixel. This is a paired-field layout check, not a complete zoom/accessibility audit.
6. With inspector, site drawer, comparison and timeline active, retain an incomplete numeric draft, click **Hide panels**, and assert the header/inspector/drawer/timeline/comparison/camera/view tools are actually invisible. Only the scene and restore control remain. **Show controls** restores prior visibility and the numeric draft without changing canonical scenario state. Keyboard activation is used to reach nonmodal controls occluded by the comparison pane; no forced clicks or DOM hiding are used.
7. In a fresh reduced-motion context, site arrival is immediate without outgoing/rotating/approaching phases.

All page errors and console errors fail the run. Offline routing aborts and records every HTTP(S) attempt; any such attempt fails the offline assertion, even if the application could otherwise continue. Native file/blob/data resources remain available. Request/resource timing records distinguish response size from actual transfer size; cached response events are not automatically counted as full repeat network transfers. Separate contexts naturally have separate cold caches.

Frame statistics include both the full session and DOM-announced navigation windows. These are observed `requestAnimationFrame` intervals, not physical event timing or a hard frame-budget guarantee. A mostly idle full-session median must not hide the maximum transition stall. Phase offsets are presentation choreography; they do not improve hourly science evidence or establish exact physical event times.
