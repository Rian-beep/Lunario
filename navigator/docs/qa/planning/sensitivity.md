# Finite sensitivity and tested alternatives

Engine-only T11/T12 implementation. UI remains parent-owned and is not claimed complete.

`runSensitivity(catalog, manifest, base, axes, {signal?, onProgress?})` returns a promise of `{baseKey,key,axes,cases,counts}`. Axes are `{field,values}` for arrivalOffsetHours, loadMultiplier, batteryWh, initialSoc, arrayHeightM or antennaHeightM. Supply one/two unique fields, 1–9 explicit finite values per field; at most 81 cases. Cases use input order, last axis fastest, and contain `{values,state,assessment,error,changedPaths}`. Baseline and axes are cloned. Baseline/axis structure errors throw; invalid individual variants retain values and error with null state/assessment. No silent date trim or substituted height. Signed arrival offsets must align exactly with catalog stepHours and shift both inclusive endpoints together. Zero capacity, load, charge and height remain valid where the scenario schema permits them; negative capacity/load/charge and unsupported heights fail. Unsupported custom-site prepared channels are evaluated as unavailable, preserving their exact requested state.

Every valid variant calls the shared evaluateScenario authority. No physics is duplicated. Counts retain all five assessment outcomes and invalid separately. UI wording: **Results across these tested cases**. These finite experiments are not probabilities or confidence bounds. Unknown custom masks remain unknown; partial scientific evidence remains conditional.

`onProgress({completed,total,key})` fires after each evaluated case; use key plus the caller's input generation to discard obsolete UI updates. Complete scenario, manifest, axes and model version define key; baseKey equals the authority's baseline scenarioKey. No internal cache exists. AbortSignal is checked before/after cases and callbacks; cancellation throws AbortError and returns no partial result. Cooperative scheduling yields after an approximately 8 ms batch (an individual synchronous authority evaluation cannot itself be interrupted). No callbacks follow an observed abort.

`findTestedAlternatives(baseAssessment,candidates,{baseState,includeMultivariable?})` consumes actual `{state,assessment}` candidates and returns an array of exact cloned states/results, differences/changedPaths, multivariable, passing, conditional, label, newlyFailingConstraints and before/after constraint metrics. Explicit baseState is necessary because AssessmentResult does not contain input state. Wrong model/dataset/scenario identity throws; identity checks establish consistency, not authenticity of forged outputs. Supply actual authority outputs. No alternate evaluator or status is invented.

One-field alternatives are default. An arrival shift preserving stay length is one conceptual variable; site changes are one location variable. Multivariable candidates require explicit opt-in and remain labelled. Supported changes are site/coordinates, arrival endpoints, battery/load/initial charge and independent prepared heights; relaxing requirements, editing evidence or changing unrelated settings is excluded. Only whole `passes-assessed` means passing; conditional, incomplete, failed and not-configured remain distinct and inspectable. A reserve cure that still fails outage is never called passing. Sparse capacity suggestions say **Smallest passing capacity among tested values**, never minimum required battery. Empty results mean no eligible tested alternatives; callers must separately explain when no returned alternative passes. Applying/saving uses the returned exact state, preserving baseline.

Cases cover deterministic 3×3 order, no baseline mutation, charge, actual time step alignment, unsupported heights, date bounds, cancellation, authority equivalence, whole-assessment failure, identity, multivariable gating and sparse wording.
