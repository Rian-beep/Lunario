# Comparison assessment integration

Comparison accepts `manifest?: EvidenceManifest | null`. Omission uses the bundled manifest, parsed locally; explicit null preserves saved rows with an evidence-unavailable message and no computed pass. The root should pass its loaded manifest. An unsupported saved stay also remains inspectable with an explicit assessment error rather than being omitted or shortened.

Each row calls `evaluateScenario` with its saved canonical state. Terrain/sphere power, storage, contact and overlap metrics consume the shared assessment. The saved array/antenna heights and operations remain independent. Sunlight and darkness are derived from the corresponding mission's known timeline; missing timeline values never become favorable percentages. No second mission evaluator or weighted score is introduced.

The existing column chooser/reordering adds assessment outcome, first known failure UTC, required-unknown count, dataset version, model version, reserve margin and known solar coverage. Default columns include outcome and required unknowns. Existing saved column preferences are retained. Numeric deltas are shown only for numeric columns; status/version/time fields are not subtracted. Default order uses assessment outcome class. Both numeric and textual column sorts keep null unknowns last in either direction. Custom numeric annotations remain editable and explicitly cannot change an assessment or certify a site.

The first cell retains scenario opening, dates, reference selection and removal. Duration now uses the actual catalog stepHours. Its collapsed evidence section preserves every required and nonrequired constraint, state, reason, actual/limit/margin, evidence IDs, model/data versions, warnings and first-failure bracket. Stale external report reasons remain visible. No known first failure does not establish a pass when required evidence is missing.

Reference-relative changes use `diffScenarios` and `classifyScenarioDiff`. Labels distinguish identical, site-only, date-only, mixed-input and free-input comparisons. Every changed schema input displays its before/after value. CSV retains chosen built-in/custom columns, full assumptions, comparison classification, changed assumptions and full assessment JSON (or explicit error).

Validation: `node --import tsx --test tests/comparison-assessment.test.ts tests/scenario-diff.test.ts` covers server-rendered assessment/evidence/change output and missing-manifest behavior, plus existing deterministic nested-input diff fixtures. `npx tsc --noEmit` checks integration. No browser/server/build ran in this worker. Integrator still needs browser checks for configurable column ordering, both sort directions with unknown rows, reference changes, custom annotation editing and CSV download. The server-rendering tests do not establish interactive or screen-reader conformance.
