# Reproducible decision packages (T14 foundation)

`lib/decision-export.ts` owns portable decision data, recomputation on import, a readable CSV and escaped printable HTML. No UI handlers or standalone changes are included in this module commit.

## Integration API

- `createDecisionPackage(catalog, state, manifest, baseline?)` validates/migrates the full scenario against the catalog's actual site IDs, sample count and step; resolves context; and calls the authoritative `evaluateScenario`. It accepts no supplied verdict. Returns a JSON-portable `DecisionPackage`.
- `stringifyDecisionPackage(package)` returns indented JSON. Nonfinite numbers become null and typed arrays become JSON arrays. UTF-8 encoded output must fit `MAX_DECISION_PACKAGE_BYTES = 1_000_000`; otherwise it throws. JSON is the canonical portable format.
- `importDecisionPackage(unknownOrJsonString, catalog, manifest)` enforces that byte limit, package version and envelope, manifest, historical constraint/evidence/time-series shapes, source fields, and the current canonical scenario validator. It recomputes via `createDecisionPackage`, throwing on unsupported dates or evidence coverage rather than clamping. Returns `{state, assessment, currentPackage, historicalAssessment, historicalManifest, historicalTrusted:false, changes, message}`. Only `assessment`/`currentPackage` are fresh authoritative results. Historical results and metadata are user-supplied, unsigned records. Import errors leave caller state untouched; root should replace current state only after this function succeeds.
- `decisionPackageCsv(package)` returns CRLF CSV with UTC interval bounds, statuses, reasons, units, constraint margins and per-interval power/stored-energy records. Nulls are blank. It uses the existing `csvCell` authority plus tab/CR protection. Strings beginning formula sigils are prefixed with an apostrophe; true numeric negatives retain their sign. CSV is a readable subset; JSON retains the full decision record.
- `printableDecisionHtml(package)` returns a standalone UTF-8 HTML string, with provenance and complete scenario assumptions first, then result, a captioned table with column/row headers, bounded events, warnings/missing assessments and sources. Every data-derived value is HTML-escaped. The HTML has print CSS and no scripts, remote fonts or PDF dependency. Root may open a Blob URL for printing and must revoke it when finished.

The package contains `packageVersion:1`, export UTC, canonical schema-2 scenario (including all requirements, operations, radio and external reports), complete assessment, model/dataset identifiers, the source manifest, source IDs/product versions/SHA-256 values as supplied by the manifest, resolved heights/horizon masks/borrowed-cell coordinates and distance, raw array/antenna forcing, interval semantics, frame, units, missing assessments and optional baseline differences. `events` collects bounded constraint violations and any future mission events; the complete assessment is serialized generically so future mission events/subsegments remain intact. No source hash is invented when the manifest has null. Source hashes are recorded provenance, not a digital signature over the decision file.

Forcing indices are inclusive, but the exported stay is `[startUtc,endUtcExclusive)`, using the next catalog epoch as the final endpoint. Every raw forcing array pairs with `index0` and `stepHours`; angular values are degrees. Null means unknown/unavailable, never zero or pass. Export timestamps do not participate in scenario identity. Only completed synchronous authoritative evaluations produce packages; cancelled search/result objects cannot be passed as an assessment to this API.

Import compares old/current dataset ID, model version, frame, source product/version/hash/coverage, plus any remaining manifest change. Changed provenance gives the exact message **“Recomputed using different evidence/model”** and `{path,before,after}` records. Even identical provenance still recomputes and explicitly labels the historical result untrusted. A user-provided external reported pass remains conditional under the shared assessment authority, and a forged stored verdict cannot change current status.

Root integration must add the import/export/print controls, display the recomputation change warning, embed the canonical manifest in standalone output, and test direct file-open workflows. Browser, print-dialog and screen-reader behavior were not tested by this isolated module workstream.
