# Physical site-to-site camera navigation

Selecting a different location while the 3D scene is mounted preserves the outgoing renderer through a camera-only Moon-body trajectory. A local view lifts to an overview, follows the shortest great-circle arc, then approaches the destination. An existing overview skips lift/rotation phases and approaches directly while orienting toward the destination. Equivalent longitude aliases do not trigger a journey.

The selected scientific state, epoch, hardware, playback state and site coordinates remain owned by the navigator. No navigation prop or navigator mutation is required. The live location is observed by the scene; old local geometry is retained for the outgoing leg. At overview distance, `SceneCameraHandoff` carries body-space camera/target/up into the new local frame before the close approach, so destination terrain can regain its proper local sampling. An already loaded original NASA Moon mesh and its texture transfer between renderers with a rigid frame transformation; its vertices are not resampled into a flat map. If the original mesh has not loaded yet, existing numerical/reference geometry remains the disclosed fallback.

The pure `lib/site-transition.ts` state machine defines phase durations, quintic phase easing, logarithmic approach radius, shortest-arc handling (including deterministic antipodes), input snapshots and generation cancellation. Latest selection starts from the actual current physical pose. Pointer/trackpad/wheel OrbitControls interaction cancels automatic motion; destination-frame handoff occurs after the gesture ends so its input is not swallowed. Camera keyboard actions also cancel navigation. Reduced-motion preference completes immediately and can be changed during a journey. Unmount cancels RAF and pending generation, aborts loading, and disposes transferred resources if no destination consumes them.

`LunarScene` announces phase changes through a small screen-reader status, with no visual toolbar or autoplay. At normal completion it retains the exact destination camera rather than resetting it through a preset. Global views retained after a canceled journey keep the globe camera mode; local completed journeys end in orbit mode. Live Sun/Earth directions are transformed through the selected site's frame into the still-mounted frame while traveling; navigation does not change the physical ephemeris.

Automated verification: `node --import tsx --test tests/site-transition.test.ts`; `npx tsc --noEmit`; targeted ESLint. Tests check phase ordering and endpoint geometry, whole-path camera radius, direct-overview approach, shortest dateline crossing and stable antipodes, retarget/cancel generation behavior, reduced motion and immutable caller inputs. No browser/server/build is run by this worker. Integrator must check actual frame continuity, repeated target clicks, drag/wheel interruption, reduced motion, local and globe starts, NASA model ownership, disposal and imagery/terrain transitions in the built application. These tests do not claim WebGL visual verification.


Independent Clevo Sol review identified and prompted fixes for handoff races: recheck a handed-off destination at consumption (including completed B followed by C); retain the outgoing original NASA mesh through its final rendered frame; defer asynchronous destination-resource remounts through the approach, then preserve the exact camera snapshot when applying deferred resources; and never select a globe preset whose minimum distance would push an interrupted pose outward. Returning to the original site during departure also retargets the current runtime rather than remounting a preset. The late-target and interrupted-overview cases have explicit pure regression tests; actual rendered continuity remains the integrator's browser gate.
